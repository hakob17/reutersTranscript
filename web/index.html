How the pipeline works

1 · Ingest Video package (HLS or MP4) + optional editorial shotlist. ffmpeg extracts mono 16 kHz audio.
→
2 · Transcribe WhisperX (Whisper large-v3 on GPU) produces the transcript with word-level timestamps.
→
3 · Diarize pyannote speaker diarization splits the audio into anonymous voices (SPEAKER_00, 01, …).
→
4 · Read on-screen names OpenCV locally detects the few frames with lower-third name graphics; only those crops go to Claude vision to be read.
→
5 · Attribute Claude merges shotlist, transcript cues and on-screen names into named speakers — with confidence and cited evidence per speaker. It never guesses.
→
6 · Publish gate Outputs: WebVTT captions, archive JSON, review transcript. Anything uncertain is flagged needs review for an editor before captions publish.

Misattribution is the failure mode to avoid, so the system is deliberately conservative: a speaker stays “Unidentified” unless there is hard evidence (self-identification, narrator hand-off, shotlist match, or an on-screen graphic). Every name carries its evidence in the JSON record.

Production proposal — AWS

S3 ingestvideo + shotlist land in a bucket → EventBridge → SQS queue (burst-proof, replayable)
→
AWS Batch · GPUg6.xlarge (L4) containers, models baked in, scales to zero when idle; Spot cuts GPU cost ~65%
→
Lambda · attributionClaude via Bedrock/API — no GPU held open during LLM calls
→
Review gateStep Functions pauses on needs review until an editor approves in the review UI, then captions publish
  • Scale-to-zero economics — no warm GPUs overnight; the queue absorbs wire-service bursts and Batch spins capacity up in 2–5 min.
  • No runtime dependency on Hugging Face — model weights are baked into the container image at build time (HF_HUB_OFFLINE=1).
  • Human-in-the-loop enforced by the workflow — the needs review state is a paused Step Function, not a convention; nothing uncertain publishes on its own.
  • Observability — CloudWatch alarms on queue depth, failure rate and the % of videos flagged for review (the early quality-drift signal).
  • Secrets — API keys live in Secrets Manager; per-video status in DynamoDB keyed by video ID (idempotent re-runs).
